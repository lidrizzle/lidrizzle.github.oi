0.2 阅读约定

写法 含义
$ command 普通用户提示符下执行
# command root（或 sudo）下执行
<user>、<host>、<path> 需要替换成你自己的值
[可选] 可选参数
粗体 重点或容易出错的地方

重要：不要盲目复制命令。

尤其是 rm -rf、chmod -R、chown -R、mkfs、dd、mount、userdel -r 这类命令，删错一个路径就可能造成不可恢复的损失。执行前先 pwd、ls，确认自己在哪、要动什么。

0.3 六条安全红线

  1. 不要在登录节点跑重计算。 登录节点是给大家登录、改文件、提交任务用的；跑 VASP/编译大软件会拖垮所有人。重活交给调度器或交互式作业。
  2. 不要 rm -rf 一个变量可能为空的路径。 例如 rm -rf $DIR/，如果 $DIR 没定义，就变成 rm -rf /。脚本开头用 set -u，删除前先 echo。
  3. 不要 chmod -R 777。 这会把所有文件变成任何人可读写执行，既不安全又会破坏 SSH 密钥权限。
  4. 改 SSH/防火墙配置前，先开第二个会话。 改完先测试，确认新会话能登录，再关闭旧会话；否则可能把自己锁在门外。
  5. 改系统配置前先备份。 cp file file.bak.$(date +%F_%H%M%S)，并记录改了什么。
  6. 不要在生产环境直接试新命令。 先在 /tmp、WSL2、Docker 或虚拟机上练。

超算通常是这样的结构：

  • 登录节点（login/head node）：给你 SSH、编辑文件、提交作业、看日志用。不要在这里跑重计算或大规模编译。

  • 共享存储：/home、/scratch、/project 等，所有节点都能看到。注意配额和清理策略。

5. 环境变量与软件配置原理

5.1 什么是环境变量

环境变量是“键=值”的字符串，存在于进程的环境里，会被子进程继承。

  • 不加 export：只是当前 shell 的普通变量，子进程看不到。
  • 加了 export：进入环境，子进程继承。
  • 子进程修改环境变量，不会影响父进程。

CS 类比：环境变量像进程的“全局配置字典”，fork/exec 时传给子进程；但每个进程有自己的一份副本。

5.12 环境配置最佳实践

  1. 一个地方配置：环境变量集中在 ~/.bashrc 或单独的 ~/.bashrc.local，不要到处 export。
  2. 幂等：重复 source 不会重复添加 PATH。
  3. 加引号：路径可能含空格，export PATH="$HOME/my bin:$PATH"。
  4. 不要 export 一切：只导出需要传给子进程的变量。
  5. 记录环境：作业日志里保存 module list、env、软件版本。
  6. **不要在 .bashrc 里 exit**：可能导致无法登录。
  7. 不要把 conda base 自动激活：可能污染其他软件。
  8. 优先 module，其次 conda/venv，最后自己编译。
  9. LD_LIBRARY_PATH 慎用：优先 rpath/module。
  10. 可复现：固定版本，保存 environment.yml、module list、编译参数。

8.1 维护者的基本原则

  1. 最小权限：能用普通用户做的，不用 root；能用 sudo 单条命令的，不 sudo -i。
  2. 先备份，再修改：配置文件改前 cp file file.bak.$(date +%F_%H%M%S)。
  3. 一次只改一件事：改完验证，再改下一件。
  4. 保留回滚路径：知道怎么撤销；LVM/ZFS 快照是好东西。
  5. 记录变更：时间、原因、命令、影响、回滚方法。
  6. 先测试语法：sshd -t、visudo -c、nginx -t、systemd-analyze verify。
  7. 保持第二个会话：改 SSH/防火墙时，旧会话不要关。
  8. 不要在生产环境跑来源不明的脚本。
  9. 监控和告警：磁盘、负载、温度、备份失败。
  10. 文档化：让下一个人（或未来的你）能看懂。

  • 计算节点：无盘/本地盘 + 共享存储。

节点维护流程

  1. 通知用户维护窗口。
  2. 排空节点（drain/offline），等待作业结束。
  3. 检查 sinfo -R / pbsnodes -a。
  4. 更新/重启。
  5. 跑健康检查（CPU、内存、磁盘、GPU、IB、共享存储）。
  6. 恢复节点（resume/clear）。

模块/编译器一致性

  • 计算节点和登录节点的 module 版本要一致。
  • MPI 编译和运行要一致。
  • 更新编译器/MPI 后，重新编译依赖软件。
  • 保留旧版本 module，避免用户作业突然失效。

  • /home 小配额，/scratch 大容量但定期清理。

  • 重要数据让用户归档到 /project 或外部存储。

五步法

  1. 现象：具体错误是什么？谁受影响？什么时候开始？

手册结束。命令细节以你所在超算/服务器的实际版本为准；生产环境操作前先在测试环境验证。
